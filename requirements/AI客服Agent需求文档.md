# AI 客服 Agent 需求文档

## 当前阶段范围

本阶段只搭建工程框架，不实现具体业务代码。

交付范围：

- Java 多模块 Maven 工程骨架
- 前后端分离目录：`backend/` 与 `frontend/`
- Agent、技能、风控、工单、知识库、通知的模块边界
- 前端、基础设施、脚本目录占位
- 混合服务模式的文档化约束

不在本阶段实现：

- 订单查询、修改地址、退款、换货等业务逻辑
- LLM 接口调用
- 数据库 DDL 和真实数据迁移
- 前端页面和交互组件
- Docker Compose、K8s、RocketMQ、Milvus 的真实配置

## 核心能力需求

| 能力 | 说明 | 风险策略 |
|------|------|----------|
| 自然语言咨询 | FAQ、售后政策、物流说明等知识类问题 | L0 |
| 查询订单 | 根据用户上下文查询订单状态、物流状态 | L0 |
| 修改地址 | 按订单状态判断是否允许 Agent 自动处理 | L1 / L2 / L3 |
| 退款申请 | 收集必要信息并发起人工审核 | L3 |
| 换货申请 | 收集必要信息并发起人工审核 | L3 |
| 人工兜底 | 低置信度、敏感操作、异常情绪、系统异常时转人工 | L3 |

## 验收标准

- `backend/pom.xml` 声明的所有 Maven 子模块均有对应目录和子 POM。
- 前端工程集中放在 `frontend/` 下，通过 `frontend/package.json` 聚合，不与后端 Maven 模块混放。
- 各模块职责清晰，不混入业务实现。
- 敏感操作默认进入人工审核，不存在自动执行入口。
- 文档能说明从用户消息到 Agent 决策再到人工兜底的完整链路。
- 后续开发人员可以按模块边界继续补契约、接口和业务适配。
