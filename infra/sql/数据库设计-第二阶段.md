# 数据库设计-第二阶段

第二阶段目标是支撑技能注册和声明式编排，让 Agent 可以把意图映射到技能，再由技能定义决定需要哪些槽位、调用哪些业务 API、如何记录执行结果。

本阶段仍然不实现订单、退款、换货、修改地址等具体业务逻辑，只定义承载这些能力的配置和日志表。

## 表清单

| 表 | 作用 | 主要写入方 |
|----|------|------------|
| `skill_registry` | 注册技能、绑定意图、定义基础风险等级和执行方式 | Skill Engine / 管理后台 |
| `skill_slot` | 定义技能需要的槽位、类型、校验和追问模板 | Skill Engine / 管理后台 |
| `skill_api_step` | 定义技能的 API 调用步骤、参数映射、回滚声明 | Skill Engine / 管理后台 |
| `skill_execution_log` | 记录技能执行请求、步骤结果、响应和错误 | Skill Engine |

## 技能编排关系

```text
skill_registry
  -> skill_slot
  -> skill_api_step
  -> skill_execution_log
```

`skill_registry.intent` 与 Agent Core 识别出的意图编码关联，例如：

- `order.query`
- `logistics.query`
- `order.modify_address`
- `order.cancel`
- `refund.apply`
- `exchange.apply`

其中 `refund.apply`、`exchange.apply` 这类敏感技能建议配置为：

- `base_risk_level = 'L3'`
- `execution_type = 'REVIEW_ONLY'`
- `enabled = 1`
- `status = 'ACTIVE'`

这表示 Agent 只收集必要信息并创建人工审核工单，不直接执行退款或换货。

## 设计原则

- 技能注册表只表达能力，不承载业务实现代码。
- 槽位定义与 API 步骤分开，方便多轮对话和技能编排独立演进。
- `params_mapping`、`body_template`、`result_mapping` 使用 JSON 保存声明式映射，后续由 Skill Engine 解释执行。
- API 步骤允许声明 `rollback_endpoint`，但当前阶段不实现回滚逻辑。
- `skill_execution_log` 只记录执行过程和结果，正式订单、退款、换货状态仍由电商业务系统维护。

## 与第一阶段表的关系

`skill_execution_log` 关联：

- `cs_session`
- `cs_message`
- `skill_registry`

这样可以从一次技能执行追溯到用户会话、触发消息、Agent 风控决策和具体技能定义。
