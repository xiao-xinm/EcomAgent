# 数据库设计-第三阶段

第三阶段目标是把“风控规则 + 人工审核 + 人工接管”落成结构化数据，支撑敏感操作和异常场景的人工作业闭环。

本阶段仍然不实现具体业务动作，只建立规则、审批和接管的状态流转基础。

## 表清单

| 表 | 作用 | 主要写入方 |
|----|------|------------|
| `risk_rule` | 保存风控规则、命中条件、目标风险等级和路由决策 | 管理后台 / Agent Core |
| `approval_task` | 保存退款、换货、高风险修改等人工审批任务 | Agent Core / Workbench |
| `approval_action` | 保存审批任务操作轨迹 | Workbench |
| `human_takeover` | 保存人工接管请求、分配、开始和结束记录 | Gateway / Agent Core / Workbench |

## 设计原则

- `risk_rule` 只保存规则配置，不在数据库中执行表达式。
- `approval_task` 与 `work_order` 绑定，保持工单视角和审批视角都能追溯。
- `approval_action` 保存每次状态变更前后的状态，便于审计和排查。
- `human_takeover` 独立于审批任务，支持低置信度、用户主动要求、系统异常等非审批场景。
- 所有关键表保留 `trace_id`，与第一阶段主链路追踪打通。

## 敏感操作建议

退款和换货应进入：

- `work_order`
- `approval_task`
- `approval_action`
- 必要时进入 `human_takeover`

对应技能种子已配置为：

- `refund.apply`: `L3 + REVIEW_ONLY`
- `exchange.apply`: `L3 + REVIEW_ONLY`
