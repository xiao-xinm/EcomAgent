# 数据库设计-第一阶段

第一阶段目标是支撑客服 Agent 的最小主链路：

```text
用户发起消息
-> 保存会话和消息
-> 记录意图识别结果
-> 记录风控决策
-> 自动回复或创建人工工单
-> 人工操作留痕
-> 写入审计日志
```

## 表清单

| 表 | 作用 | 主要写入方 |
|----|------|------------|
| `cs_session` | 保存会话状态、当前意图、槽位和上下文快照 | Gateway / Agent Core |
| `cs_message` | 保存用户、Agent、人工坐席和系统消息 | Gateway / Agent Core / Workbench |
| `intent_record` | 保存每次 NLU 意图识别结果和实体 | Agent Core |
| `risk_decision` | 保存 L0-L3 风控等级和路由决策 | Agent Core |
| `work_order` | 保存需要人工审核或人工接管的工单 | Agent Core / Workbench |
| `work_order_action` | 保存人工工单的操作轨迹 | Workbench |
| `audit_log` | 保存关键事件审计日志 | 全后端服务 |

## 设计原则

- 表结构只承载主链路底座，不包含订单、退款、换货等电商业务表。
- 枚举值与 `smartcs-common` 中的 Java 枚举保持一致。
- 所有关键表保留 `trace_id`，便于后续链路追踪。
- 会话、消息、工单和审计数据分开存储，避免单表职责过重。
- `JSON` 字段用于保存上下文快照、槽位、实体、规则命中详情等半结构化数据，正式业务字段后续再逐步收敛。
- 审计日志中的 `user_id`、`event_data` 在生产写入前应由调用方完成脱敏。

## 风险与人工链路

`risk_decision.route_decision` 与 `work_order.route_decision` 使用统一值：

- `AUTO_REPLY`
- `AUTO_EXECUTE`
- `CONFIRM_BEFORE_EXECUTE`
- `HUMAN_REVIEW`
- `HUMAN_TAKEOVER`
- `REJECT`

敏感操作，如退款、换货、高金额补偿和异常情绪投诉，应落到：

- `risk_level = 'L3'`
- `route_decision IN ('HUMAN_REVIEW', 'HUMAN_TAKEOVER')`

Agent 不直接执行 L3 操作，只创建或转交人工工单。
